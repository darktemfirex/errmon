# 오류 모니터링 · 조치 우선순위

BXM(물류센터 WM) 오류 로그 엑셀을 읽어 **꼭 조치해야 할 거래**를 추리고, **일자별 발생 추이**를 보여 주는 정적 웹앱입니다. 서버 없이 브라우저에서 동작합니다.

## 화면 구성
1. 요약 카드 – 전체 오류, 즉시 조치/조치 검토 개수, 최근 14일 증감
2. **꼭 조치해야 할 내역** – 즉시 조치 등급만 카드로 (근거, 의심 쿼리, 권장 조치)
3. 전체 우선순위 표 – 등급 탭·검색, 행을 누르면 쿼리/이력/SQL 펼침
4. **일자별 추이** – 일/주/월, 거래별 선택, 급증일 표시, 시간대·요일·서버 분포, 주간 히트맵, 월별 비교
5. 점수 계산 방식 (화면 맨 아래)

## 보고서 저장 (세션이 끝나도 남기기)
화면 위의 **보고서(TXT)** 버튼을 누르면 분석 결과 전체가 텍스트 파일로 내려받아집니다(`오류분석보고서_<기간>_작성<일시>.txt`, UTF-8).
요약 → 즉시 조치(근거·의심 쿼리·테이블·권장 조치·최근 이력·SQL 샘플) → 조치 검토 → 관찰 목록 → 월별/주별/일별/시간대/요일 추이 → 점수 기준 순서입니다. 사용자 IP는 들어가지 않습니다.
화면 내용은 새로고침하면 사라지므로, 필요한 분석은 보고서로 저장해 두세요. 표만 필요하면 **우선순위 CSV** 도 있습니다.

## 데이터 갱신
- 화면에서: **엑셀 불러오기**로 새 엑셀(여러 개 동시 선택 가능)을 고르면 그 데이터로 분석합니다. 새로고침하면 내장 데이터로 돌아갑니다.
- 내장 데이터 교체: 엑셀을 `monitor_system` 폴더에 두고 아래 실행 → `data.json` 이 새로 생깁니다.

```bash
node scripts/build-data.cjs
```

## 앱으로 설치 (PWA)
HTTPS(또는 localhost)로 열면 브라우저 메뉴의 **앱 설치 / 홈 화면에 추가**로 설치할 수 있습니다.
- 화면 구성 파일(HTML/CSS/JS, 엑셀 파서)은 서비스 워커(`sw.js`)가 캐시해서 오프라인에서도 열립니다. 네트워크가 되면 항상 최신 배포를 먼저 받습니다.
- **`data.json`과 불러온 엑셀은 캐시·저장하지 않습니다.** (사내 로그 데이터라 기기에 남기지 않기 위함) 오프라인에서 분석하려면 엑셀을 다시 불러오세요.
- 앱 셸 파일을 바꾸면 `sw.js`의 `CACHE` 버전(`errmon-v1`)을 올리세요.

## 로컬 확인 / 테스트
```bash
node scripts/serve.cjs 5180   # http://localhost:5180
node --test                   # 분석 로직 테스트
```

## 엑셀 형식
`TRX_CD`, `LOG_OCCUR_DTTM` 컬럼이 있는 행을 헤더로 인식합니다(위에 제목 행이 있어도 됩니다).
사용 컬럼: TRX_CD, SCREEN_ID, LOG_OCCUR_DTTM, NODE_NM, CONTAINER_NM, SEND_USER_IP, ERR_CD, ERR_MSG_CTT, ERR_STACKTRACE, SQL_ERR_CD, LINK_SEQ, TRX_GUID.

**사용자 IP(SEND_USER_IP)는 저장·표시하지 않습니다.** 읽는 즉시 임의 값을 섞은 해시 토큰으로 바꿔 "서로 다른 사용자 수" 계산에만 쓰고, 토큰도 읽을 때마다 새로 만들어 IP로 되돌릴 수 없습니다.

## 우선순위 기준 (core.js 의 `DEFAULTS`)
거래(TRX_CD) 단위 100점: 최근 30일 건수 35 + 발생 일수 25 + 월 지속 15 + 영향 사용자 수 10 + 최근 14일 급증 15.
70점 이상 즉시 조치, 40점 이상 조치 검토, 그 밖은 관찰. 최근 30일 미발생이면 관찰로 내리고, 급증이면 올립니다.
`ORA-00600/07445/04031/01555/01652~01654/03113` 이 나오면 점수와 무관하게 즉시 조치입니다.

## 주의
`data.json` 에는 SQL 샘플과 서버·거래 정보가 들어 있습니다(IP는 없음). 배포할 때는 비공개 앱으로 두세요.
